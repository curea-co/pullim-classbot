## 1. AI 명령지침 (이 spec 한정)

- 이 문서를 단일 진실원으로 본다. 권위 문서와 충돌하면 권위 문서를 따르고 본 spec을 갱신한다.
- **개발 시작 전 반드시 검토할 것**:
  1. `gradingQueue` mock의 모든 필드를 화면에서 소비하는지
  2. "AI 초안 = 제안, 교사 = 판결" 디자인 원칙 (핸드오프 § 2.5) 위반하지 않는지
  3. 객관식·서술형·단답형 3타입 모두 동일 큐에서 처리되는지
  4. **채점 대기가 없는 학생도 목록에 남는지** — 채점 허브는 「채점할 게 있는 학생」이 아니라
     **등록된 학생 전체**를 본다. 큐만 보이면 오늘 제출하지 않은 학생이 화면에서 사라진다
  5. 학생 상세를 새로 만들지 않았는지 — 대화 기록·막힌 지점·과정 평가는 `/teacher/students/[id]` 가 이미 한다
- 추출본 정책: 다른 도메인(플래너/Q/라이브러리) 의존 금지. 채점 허브는 클래스봇 단일 도메인 내부에서 자급한다.
- **금지**: AI 점수를 학생/학부모에게 직접 노출. 반드시 교사 승인 후에만 학생·학부모 가시.

## 2. 제품 정의 (Problem · Goal · Persona)

### 2.1 Problem Statement
공교육 교사·학원 강사의 서술형 채점은 1인당 2주 → 평균 채점 소요시간이 학생 피드백 사이클을 끊는다. 객관식은 자동화됐지만 서술형·단답형은 여전히 수작업이고, 채점 일관성도 교사 컨디션에 좌우된다.

### 2.2 Product Goal
- **G1**: 서술형 채점 소요시간 **80% 단축** (KPI § 10.2)
- **G2**: 교사는 "초안 검수자"로 역할 전환 — 점수 작성 → 점수 확인·수정
- **G3**: 교사 수정 데이터가 루브릭 재학습으로 환류 (선순환 폐쇄)

### 2.3 Persona별 영향

| 페르소나 | 역할 | 이 기능에서 무엇이 달라지나 |
|---|---|---|
| **P1 교사** (주) | 채점자 | 큐에 쌓인 AI 초안을 검수·승인. 변경률 20% 초과 시 루브릭 재학습 제안 수락 |
| **P2 학생** | 응시자 | 제출 후 평균 24시간 → 6시간 내 피드백 수신 |
| **P3 학부모** | 열람자 | 최종 점수만 노출 (AI 초안은 안 보임) |
| **P4 학원 관리자** | 감독자 | 강사별 검수 평균 소요 / 변경률 KPI 열람 |

## 3. 핵심 기능 정의 (FSD)

### 3.1 MoSCoW

#### Must (MVP)
- [M0] **등록 학생 전체 목록** — 기본 화면. 채점 대기가 0건인 학생도 빠지지 않는다
- [M0-1] 학생 한 줄 요약을 **배지**로 — 도달 상태 · 최근 접속 · 채점 대기 건수
- [M0-2] 학생을 누르면 `/teacher/students/[id]` 상세로 — 어떤 봇과 무슨 대화를 했고 어디서 막혔는지
- [M1] 채점 큐 화면 — 상태별 필터 (대기/검토중/완료)
- [M2] 채점 상세 화면 — AI 초안 + 루브릭 항목별 점수 표시
- [M3] 교사 인라인 편집 — 점수·코멘트·루브릭 항목 수정
- [M4] 승인 / 오버라이드 액션 — 학부모 가시화 트리거
- [M5] 변경률 자동 계산 + 20% 임계 알림

#### Should (v1)
- [S1] 상위 10% / 하위 10% 자동 분석 패널 (T3)
- [S2] 일괄 작업 — 다중 선택 → 일괄 승인
- [S3] 루브릭 재학습 제안 모달 — 교사 승인 시 다음 과제부터 적용
- [S4] 학생별 채점 이력 사이드 패널

#### Could (v2)
- [C1] 손글씨 답안 OCR + 채점 (수학 풀이 과정)
- [C2] AI 음성 코멘트 자동 생성 (교사 목소리 TTS)
- [C3] 표절·AI 작성 의심 플래그

#### Won't (현 단계 제외)
- 자동 점수 학부모 직접 발송 (반드시 교사 승인 게이트 통과)
- AI가 만점 처리 (모든 항목 최소 1초간 교사 시선 보장 — 안티 패턴 방지)

### 3.2 Sitemap 변경

```
/teacher
├─ /teacher/grading                 ← 채점 허브 입구
│  ├─ ?view=students                ← **기본** · 등록 학생 전체 (배지 요약)
│  ├─ ?view=queue                   ← 채점 대기 큐 (필터·정렬·일괄 액션)
│  ├─ /teacher/grading/[id]         ← 채점 상세 (AI 초안 검수)
│  └─ ?status=…&type=…              ← URL 상태 (큐 화면 한정)
│
└─ /teacher/students/[id]           ← 학생 상세 — 채점 허브 목록이 여기로 보낸다 (신규 아님)
```

두 화면을 한 라우트 안에서 **탭으로** 가른다. 거르개를 두 벌 겹쳐 두지 않기 위해서다 —
학생 목록의 거르개(도달·접속·채점 대기)와 큐의 거르개(상태·타입)는 서로 다른 것을 거른다.
같은 화면에 함께 두면 지금 무엇이 걸려 있는지 읽을 수 없다.

학생 영역에 채점 진입 없음 — 학생은 "결과 보기" CTA로 [학생 과제 풀이 결과 페이지](12-student-assignment-solve.md § 3.2)에서 최종 점수만 확인.

### 3.3 Screen Spec

#### 3.3.0 학생 전체 (`/teacher/grading?view=students`) — **기본 화면**

| 구성 | 설명 |
|---|---|
| **상단 KPI 바** | 채점 큐와 같은 4칸 (대기 · 검토중 · 오늘 승인 · 평균 변경률) |
| 탭 | `학생 전체`(기본) · `채점 대기 큐` |
| 거르개 | 전체 · 채점 대기 있음 · 미도달 · 오늘 안 들어옴 |
| 정렬 | 채점 대기 많은 순(기본) · 이름순 · 활동 오래된 순 |
| **학생 행** | 이름·학년 / 도달 배지 / 최근 접속 배지 / 채점 대기 배지 / 막힌 개념(첫 한 가지) / 대기가 있으면 그 한 건의 AI 초안 점수 |
| 행을 누르면 | `/teacher/students/[id]` — 대화 기록 · 막힌 지점 · 과정 평가 |
| 빈 상태 | 거르개에 걸린 학생이 없을 때만. **등록 학생이 0명이 아닌 한 목록은 비지 않는다** |

배지가 말하는 것과 그 출처:

| 배지 | 무엇을 말하나 | 출처 |
|---|---|---|
| 도달 (도달·미달·미도달) | 성취기준에 닿았는지, 요구한 사고 수준까지 갔는지 | `reachBadge()` — 관제소·교사 홈과 같은 판정 |
| 최근 접속 | 마지막 활동이 언제였는지, 오늘 들어왔는지 | `lastSeenText()` · `isOfflineToday()` |
| 채점 대기 | 이 학생 앞으로 검수할 채점이 몇 건인지 (0건이면 「대기 없음」) | 교사 확정(store) 반영 후 `status === 'queue'` 인 건수 |

**없는 지표를 새로 만들지 않는다.** 세 배지 모두 이미 다른 화면이 쓰던 판정을 그대로 읽는다 —
같은 학생이 화면마다 다르게 읽히면 안 된다.

#### 3.3.1 채점 대기 큐 (`/teacher/grading?view=queue`)
| 구성 | 설명 |
|---|---|
| **상단 KPI 바** | 대기 N건 · 검토중 N건 · 오늘 승인 N건 · 평균 변경률 N% |
| 필터 칩 | 상태(`queue/reviewing/approved/overridden`), 타입(`essay/short/numeric`), 봇, 과제 |
| 정렬 | 제출 시간 / AI 신뢰도 / 위기 신호 우선 |
| **채점 행** | 학생명·과제·타입·AI 점수·신뢰도·상태·"검수" CTA |
| 위기 신호 인디케이터 | `aiConfidence < 70` 또는 응답 빈약·감정 키워드 |
| 일괄 액션 바 | 다중 선택 시 노출 — "선택 N건 승인" / "일괄 오버라이드" |
| 사이드 패널 (lg+) | 오답 클러스터 TOP 3 (이 과제 한정) — 패턴별 학생 수 |

큐는 **지우지 않는다.** 교사가 「오늘 채점할 것」만 보고 싶은 때가 있고, 상태·타입 거르개와
AI 신뢰도 정렬은 그때만 쓰인다. 기본 화면이 학생 전체로 바뀌었을 뿐이다.

#### 3.3.2 채점 상세 (`/teacher/grading/[id]`)
| 구성 | 설명 |
|---|---|
| 헤더 | 학생명·과제명·제출 시각·"이전/다음 학생" 네비 |
| 좌측 — 문제 + 학생 응답 | KaTeX 렌더 · 학생 원본 텍스트 · OCR (있을 시) |
| 중앙 — 루브릭 카드 | 항목별 (criterion · weight · score · reason) · 인라인 슬라이더로 점수 수정 |
| 우측 — AI 초안 코멘트 + Tier 표시 | 교사 편집 가능 textarea · 변경 시 변경률 실시간 표시 |
| **변경률 패널** | 점수·코멘트 변경 % · 20% 초과 시 "루브릭 재학습 제안" 활성 |
| 액션 바 | `[승인]` · `[수정 후 승인]` · `[전체 재채점 요청]` · `[1:1 면담 메모]` |
| 사이드 — 이 학생 최근 5회 | 과거 채점 이력 추세 (점수·코멘트 유형) |
| 위기 게이트 | 응답에 자살·우울 키워드 발견 시 자동 경고 모달 (3자 알림 트리거) |

#### 3.3.3 학생 상세 (`/teacher/students/[id]`) — 채점 허브가 보내는 곳

**새로 만들지 않는다.** 이미 있는 화면이고 대화 기록 뷰어·과정 평가·이탈 이력이 들어 있다.
채점 허브에서 학생을 눌러 들어왔을 때 답해야 하는 질문 세 가지만 채운다.

| 질문 | 어디가 답하나 |
|---|---|
| **어떤 봇과** 대화했나 | 헤더 (`학급 · 봇 이름 · 단원`) + 대화 기록 뷰어의 말하는 이 이름 |
| **어떤 대화**를 했나 | 대화 기록 뷰어 — 턴 단위 · 범위 이탈 표시 · 지름길 표시 |
| **어디서 막혔나** | **「막힌 지점」 패널 (신규)** — 막힌 개념마다 학생이 실제로 한 질문과 봇이 되짚은 말을 붙여 보여준다 |

「막힌 지점」 패널:
- 원천은 `MonitoredStudent.stuckConcepts` 하나뿐. 학급 「다시 가르칠 개념」과 **같은 값**을 읽는다
- 개념 이름 옆에 그 개념을 다룬 대화 턴(학생 질문 · 봇 되묻기)을 그대로 붙인다 — 새로 지어내지 않고 기록에서 뽑는다
- 막힌 개념이 없으면 그렇게 적는다. 빈 자리를 다른 지표로 메우지 않는다
- 이 학생의 채점 대기가 있으면 그 항목으로 돌아가는 링크를 함께 둔다 (채점 허브 ↔ 학생 상세 왕복)

## 4. UX Flow

### 4.1 Flow G1 — 교사 일상 채점 (가장 빈번)
```
1. 교사 홈 → "서술형 채점 대기 12건" 카드 클릭
2. /teacher/grading 진입 → 큐 정렬: AI 신뢰도 낮은 순
3. 첫 번째 학생 행 클릭 → 상세 진입
4. 루브릭 점수 1개 수정 (-2) + 코멘트 한 줄 추가
5. [수정 후 승인] → 다음 학생 자동 이동
6. 일관 패턴: 5명 채점 = 약 7분 (수동 30분 → 80% 단축)
```

### 4.1-b Flow G0 — 오늘 제출하지 않은 학생 찾기 (기본 화면)
```
1. 교사 홈 → 「채점 허브」 진입 → 기본은 「학생 전체」 탭
2. 20명이 배지 세 벌(도달 · 최근 접속 · 채점 대기)로 한 줄씩 보인다
3. 채점 대기 0건인데 도달 배지가 「미도달」인 학생이 눈에 걸린다
4. 그 학생을 누름 → /teacher/students/[id]
5. 대화 기록에서 어떤 봇과 무슨 말을 주고받았는지, 「막힌 지점」에서 어디서 걸렸는지 확인
6. 채점 큐만 보던 때에는 이 학생이 화면에 아예 없었다 — 그게 이 화면을 바꾼 이유다
```

### 4.2 Flow G2 — 루브릭 재학습 환류
```
1. 교사가 같은 항목("표기 정확성")을 5명 연속 -5점 추가 차감
2. 시스템: 변경률 누적 24% — 임계 초과
3. 상세 페이지 우측에 "루브릭 재학습 제안" 카드 점등
4. 교사 클릭 → 변경 패턴 요약 모달
5. [다음 과제부터 적용] → 루브릭 v2 활성, 이력 감사 로그 기록
```

### 4.3 Flow G3 — 위기 신호 발견 (응답 빈약)
```
1. 학생 도현 응답 = "잘 모르겠음. 미분이 너무 어렵다"
2. AI 초안: 8/20 · aiConfidence 58 · 코멘트에 "응답 부족"
3. 큐에서 위기 인디케이터 점등
4. 교사 진입 → "1:1 면담 메모" 클릭
5. 메모 작성 → 리포트 센터의 학생 개인 리포트에 자동 첨부
6. 도현이 다음 로그인 시 "선생님이 도현이를 응원해" 알림 (점수 노출 전)
```

## 5. 운영 로직 (Business Rules)

### 5.1 변경률 계산식
```
overrideDelta = |draftScore - finalScore| / maxScore × 100
```
- 누적 변경률 = 최근 30일 평균
- 30일 평균이 임계(20%) 초과 시 자동으로 루브릭 재학습 제안

### 5.2 상태 전이
```
queue ──교사 진입──> reviewing ──저장──> approved
                                  └──수정──> overridden  (overrideDelta 저장)
```
- `approved`와 `overridden` 모두 학부모·학생에게 가시화되는 종착 상태
- 재학습 후 같은 항목에 대해 점수가 자동 재계산되더라도 종착 상태는 보존

### 5.3 자동 처리 규칙
- `type === 'short' && aiConfidence ≥ 95` → T1 자동 채점 + 자동 승인 (교사 검수 스킵)
- `type === 'essay'` → 무조건 교사 검수 필수
- `type === 'numeric'` → 정답 일치 시 자동 승인, 부분 점수 케이스만 큐 진입

### 5.4 위기 게이트 (자동 차단)
응답 본문에 다음 정규식 매치 시 점수 표시 전에 경고 모달:
- 자살·자해 관련 키워드 (사전 정의 화이트리스트 기반)
- 감정 체크인 직전 3일 "힘듦" 누적 학생 응답

게이트 통과 후에만 점수 화면 노출. 동시에 [13. 리포트 + 감정 체크인](13-reports-and-emotion-checkin.md § 6.2) 의 3자 알림 트리거.

### 5.5 검증 규칙
| 항목 | 제약 |
|---|---|
| `rubric` 합 | 항상 100 (검증 실패 시 저장 차단) |
| 항목별 점수 | 0 ≤ score ≤ weight × 1.0 |
| 코멘트 길이 | 10 ≤ length ≤ 500자 |
| 승인 후 수정 | 금지 (수정 필요 시 별도 "재채점 요청" 로그) |

### 7.1 채점 항목 ↔ 등록 학생 명단 잇기

두 mock 이 **같은 교실을 따로 적었다.**

| | 파일 | id | 이름 표기 | 인원 |
|---|---|---|---|---|
| 채점 항목이 쓰는 명단 | `classbot.ts` · `classRoster` | `s1`~`s18` | 이름만 (`서연`) | 18 |
| 학생 목록·상세가 쓰는 명단 | `classbot-monitoring.ts` · `monitoredRoster` | `m01`~`m20` | 성까지 (`김서연`) | 20 |

채점 허브가 「등록된 학생 전체」를 보여주려면 둘을 이어야 한다. 잇는 규칙은 **번호 그대로**(`sN` ↔ `m0N`)다.
근거 — 채점 시드 7건 중 5건이 번호도 이름도 함께 맞는다:

| 채점 시드 | 학생 명단 | 이름 |
|---|---|---|
| `gr_002` `s1` 서연 | `m01` | 김**서연** ✅ |
| `gr_004` `s4` 도현 | `m04` | 최**도현** ✅ |
| `gr_006` `s6` 주원 | `m06` | 강**주원** ✅ |
| `gr_007` `s9` 나린 | `m09` | 임**나린** ✅ |
| `gr_001` `s13` 윤서 | `m13` | 신**윤서** ✅ |
| `gr_003` `s2` 민준 | `m02` | 이준서 — 번호 규칙만 |
| `gr_005` `s5` 하윤 | `m05` | 정예린 — 번호 규칙만 |

**반례가 없다** — 이름이 겹치는 5건이 모두 번호도 같다. 그래서 이름이 갈리는 2건도 같은 규칙으로 잇는다.

채점 허브에서 `민준`, 학생 상세에서 `이준서` 로 갈리면 같은 사람인지 알 수 없다.

시드를 손대지 않고 **읽을 때 잇는다**(`linkGradingItems()`). 채점 시드는 다른 화면·테스트도 읽기 때문이다.

## 8. 브랜딩 / UX Writing

### 8.1 톤
교사를 "판결자"가 아닌 "마지막 검수자"로 호칭. AI 초안은 항상 "초안" 또는 "제안"으로 표기 — 결코 "AI 채점 결과"라고 단독 표현 금지.

### 8.2 마이크로카피 테이블

| 상황 | 카피 |
|---|---|
| 큐 빈 상태 | "검수할 채점이 없어요. 학생들이 새로 제출하면 여기에 쌓여요." |
| 학생 목록 기본 설명 | "등록된 학생 전체예요. 채점할 게 없는 학생도 함께 보여요." |
| 채점 대기 0건 배지 | "대기 없음" |
| 학생 목록 거르개 빈 상태 | "이 조건에 해당하는 학생이 없어요." |
| 막힌 지점 없음 | "이 학생이 막힌 개념은 기록에 없어요." |
| AI 신뢰도 낮음 | "AI 신뢰도가 낮아요. 직접 보고 정하는 게 안전해요." |
| 변경률 20% 초과 | "루브릭이 학생 답과 어긋나는 것 같아요. 기준을 다시 학습할까요?" |
| 위기 게이트 발동 | "도현이 응답에 신경 쓸 표현이 있어요. 점수 전에 한 번 더 봐주세요." |
| 일괄 승인 확인 | "선택한 N건을 그대로 승인할게요. 되돌릴 수 없어요." |
| 재학습 제안 수락 | "다음 과제부터 새 기준이 적용돼요. 이전 점수는 그대로 남아요." |

### 8.3 금지어
- "AI가 채점했어요" → "AI 초안이에요"로 교체
- "정답" → 서술형은 "기준 응답" 또는 "모범 응답"
- "오답" → "보완 필요" (학생 가시 영역)
